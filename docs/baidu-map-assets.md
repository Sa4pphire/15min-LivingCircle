# 固定地图数据与请求说明

## 已消除的请求

之前 `RealMapStage.vue` 在每次创建地图时，用浏览器 `BMap.Convertor` 串行转换 168 个边界顶点、中心点和展示范围：约 19 次转换调用。快速／专家模式使用不同 key，又会销毁并重建地图，使这些请求重复发生。

现在前端直接打包读取 `frontend/src/data/demoMap.bd09.json`，初始化时坐标转换调用为 **0 次**。快速／专家模式只切换输入和结果图层，不重建地图。进入局部实验后，已加载的地图暂时隐藏并保留；直接以 `?mode=local` 打开时，百度地图仍不初始化。隐藏时不按零尺寸重新适配取景。

百度 JSAPI 和瓦片依然需要网络，缩放／拖动时的瓦片加载属于正常请求；本改动没有下载、导出或永久缓存百度底图，也不改变 Python 协作者的 POI 请求与缓存流程。

比例尺切换先用 `getViewport` 计算展示范围的基准，再设置一次绝对缩放目标；不先调用 `setViewport` 再读取尚未更新的 `getZoom`。因此大／中／小可以双向切换，不会累计放大。切档保留过渡动画；减少动态效果时直接切换，中／大档保留拖动。

## 数据生成（Python 协作者可执行）

1. 原始选区是 `frontend/src/data/demoBoundary.wgs84.json`，来源及 ODbL 署名保留在转换结果里。
2. `backend/app/map_assets.py` 使用与前端相同的局部原点 `121.505,31.333`、四周扩展 `1300` 米，计算展示范围。
3. 运行以下命令；服务端 AK 按既有后端环境配置读取，不放在命令参数或输出文件中：

```powershell
.venv/Scripts/python.exe backend/scripts/export_demo_map_bd09.py
```

使用[百度官方 geoconv/v2 接口](https://lbsyun.baidu.com/docs/webapi?title=geoconv/guide/changeposition-base)，`model=2` 将 WGS‑84 转成 BD‑09。边界／中心／四角去重后分 2 批；路网另用覆盖整个展示范围的 250 米校准网格，共 529 个锚点、6 批。每批最多 100 点并复用后端共享响应缓存；已有边界缓存升级时本次只新增 6 次请求。原始选区不改变，外围展示范围也不收缩。

生成文件包含 `schemaVersion: 1`、`coordType: bd09ll`、原始输入、BD‑09 闭合边界、中心点、展示范围四角、`alignment` 校准网格、来源及生成时间，不包含 AK。网格局部轴为东／南，与前端 SVG 一致；C++ 北正坐标仍经原有 WGS‑84 契约转换，不改写算法图。

正常启动无需执行这个脚本。再次运行且输入相同时，直接复用文件，不发请求、不改写文件，也不要求此时能提供 AK。修改边界、原点或扩展距离后再执行；只有需要强制校准时使用 `--refresh`。全部批次成功后才原子替换输出，失败保留上次有效数据。

前端会检查原始边界、原点、扩展距离与转换文件是否一致，以及闭环、点数、坐标合法性和展示范围是否退化。若修改前端原点或 `DISPLAY_PADDING_METERS`，需同步修改 Python 常量，再生成并核对地图。

## 失败与精度边界

- 边界文件失效：底图仍可显示，但暂停百度图上的选点；不能把未转换的 WGS‑84 直接当作 BD‑09。
- 浏览器 AK、JSAPI 或网络失败：回退到现有 WGS‑84 SVG 示意；不是转换失败，也不会自动尝试在线转换。
- 本地地图中心缺失：明确提示本地数据缺失，不能用错误坐标创建地图。
- 旧版只用展示范围四角做仿射映射，与 168 个独立官方边界点相比，平均误差约 28.06 米、最大 32.45 米，起点反算也受影响。现在路线、等时圈、接入线和取景点使用同一校准网格的分片双线性映射；点击选点反解同一网格，不再用全区仿射拟合。地图绘制时长线段每 125 米补采样，内洞保留；这不改变 C++ 图或边长。
- 本次静态数据对相同独立官方点的平均映射误差约 0.056 米、最大 0.127 米，中心点映射误差为 0。这是**坐标映射误差**，不是道路测绘精度或步行算法精度；OSM 与百度道路几何、双侧人行道偏移及合成连接仍可能有差异，不能据此宣称路网已现场核实。
- 校准网格损坏、退化或不覆盖选区时拒绝绘制／选点，不静默使用旧仿射或外推。不能将未转换的 WGS‑84 当作百度坐标。页面仍不调用 Convertor；重复执行脚本复用有效文件，转换请求为 0。

## 验证

`frontend/tests/mapAsset.test.mjs` 校验固定数据与原始选区匹配；`baiduMapLifecycle.test.mjs` 验证初始化不访问 Convertor、模式切换不再初始化、边界损坏不隐藏底图、SDK 失败回退及隐藏时不重新取景。现有比例尺、全圈手动适配和独立模式测试继续保留。

`frontend/tests/cppViewport.test.mjs` 还覆盖快速／专家模式双向切档、连续快速切换、从全圈返回普通比例尺，以及起点聚焦／展示中心恢复；模拟 SDK 的异步相机行为，避免“只放大、不缩小”再次出现。

`backend/tests/test_map_assets.py` 验证分批与去重、重复执行零请求、无 AK 复用、显式更新、非有限坐标拒绝及转换失败保留文件。测试用转换数据均为模拟，不替代已由官方接口生成的地图文件。
