# Vision China Terminal（VCT）前端

项目暂定名为 **Vision China Terminal**，简称 **VCT**。区域选择页、地图页和浏览器标题使用新名称；窄屏页眉显示 VCT，地图页底部动态字样沿用 `LIVING CIRCLE`。

第一页保留两个共用真实区域 SVG/百度底图、但分析结果互不混用的模式：“快速模式”调用百度采样与 Python 插值，展示近似等时圈和代表步行路线；“专家模式”通过 Python API 调用 C++，显示引擎返回的 MultiPolygon 近似等时圈与可达街段，并叠加百度候选 POI，明确区分圈内点位和模型步行可达。后者不输出未经核实的真实灰区；采样结果和合成路网结果都不是实地核实的正式报告。

模式切换位于地图底部中央，使用圆角半透明磨砂按钮；选中背景滑动，地图内容短暂淡入淡出。键盘可用 Tab 聚焦、Enter/Space 切换；开启“减少动态效果”时取消切换动画。内部模式 ID 为 `real`、`synthetic`，`?mode=synthetic` 直接打开专家模式，其他参数回退到快速模式。切换不触发计算，也不清空另一模式的结果。

## 启动

```bash
cd frontend
npm install
npm run dev
```

浏览器打开 Vite 输出的本地地址。构建检查使用 `npm run build`。测试目录不随仓库发布；本地已有测试可用 `node --test tests/*.test.mjs` 按需运行。

“快速模式”的采样分析还需启动 Python API 并配置服务端百度 AK；没有 AK 时仍可浏览 SVG 底图和选点，但不能生成在线采样结果。

### “专家模式”：Python → C++ → 页面

当前已提交建模文件，不需要再次生成。按
[`data/networks/README.md`](../data/networks/README.md) 的说明启动 C++ 引擎和 Python API，再运行 Vite。切换到“专家模式”后，选点并点击右上角的计算按钮；页面调用独立的 `/api/v1/synthetic-analyses`，随后轮询 `/api/v1/analyses/{id}`。不需要浏览器环境开关，也不影响“快速模式”的采样分析。合成路网把非主干道暂作共享通道，过街／接驳均未实地核实，页面结果**不是
经核实的真实 15 分钟步行等时圈**。API 合成数据使用 WGS-84，前端仅将其转回本地 SVG 坐标；
百度底图开启时叠加仍是近似预览。

合成模式允许在围合区内非道路位置选点：C++ 找最近的可步行边，将直线接入距离按 1.3 米／秒换算并先从 900 秒预算中扣除，例如接入花 5 分钟，沿路网只剩 10 分钟。虚线表示这条**未经核实**的估算接入，不保证穿过建筑、围墙或封闭地块；耗尽预算的选点会被拒绝。C++ 对剩余时间内的街段做截断，再生成 MultiPolygon 近似面，而不是画一个缩小版固定圆。

专家模式默认只读取共享缓存中的学校、医院、商超、公共服务及餐饮候选，不在线补缺页；不再检索或显示菜市场、药店，已有缓存保留。餐饮以 `dining` 标识，按百度“美食”分类检索，地图显示“餐”标记。先显示 C++ 等时圈，再按外接框加缓冲划分固定小网格，逐关键词读缓存、按 UID 去重，按实际 MultiPolygon（含内洞）筛选圈内点位。清单不足时明确提示，可通过显式刷新或预采集补齐，普通重复计算不会偷偷调用 API。计算及 POI 更新保留比例尺和拖动位置；查看完整结果时手动点击“全圈”。分类筛选不调用百度，报告分别列出检索候选、圈内候选和圈内模型可达数量。圈内为 0 不表示真实设施匮乏。详细对接见 [百度 POI 集成说明](../docs/baidu-poi-integration.md)。

### 专家模式：按需 POI 路径

专家模式默认只展示等时圈面与 POI，不再叠加全部可达道路。地图点击 POI，或在第二页设施列表点击名称，
会通过 `/api/v1/analyses/{analysisId}/poi-route` 请求 C++ Dijkstra 路径；列表点击仍返回第一页并定位高亮。
地图只绘制当前选中的一条路径，带描绘动画、步行耗时和过街等待；未核实起点接入采用虚线。
快速切换 POI 会取消旧请求，关闭详情、换起点、重新分析或退出专家模式都会清除旧路线。
定位和路径返回均不改比例尺。没有绑定入口时，合成模式将 POI 投影到最近的可步行边，
沿路网到投影点后用直线穿越地块接入 POI；最后一段计入距离和耗时，用棕色虚线明确标为未核实。
这一估算没有核查建筑、围墙或通行权限，不更新正式设施可达统计，也不增加图上免费换侧连接。
有绑定入口时仍使用原入口；缺坐标、路网不连通或上下文过期会提示。近似面内的 POI 也可能超过 15 分钟。

后端必须使用更新后的 C++ 二进制并重启；旧分析须重新计算，以取得 `analysisId` 和路由上下文。
本地启动脚本现在默认选择 Debug；可在仓库根目录设置 `CPP_ENGINE_PATH` 指向本次构建的 `cpp-engine/build/poi-route/Debug/isochrone_engine.exe`。

### 专家模式：先显示范围，再补充设施

第一轮 C++ 返回后，轮询接口即提供可绘制结果，不再等待设施检索结束。客户端使用 `resultRevision`
只接收新版本；后续轮询带 `afterRevision`，相同版本不重复传输整幅地图。POI 补充保持已绘制的面、比例尺和拖动位置；
此时可以重新选点，旧请求会取消，不能覆盖新起点的结果。界面沿用原布局，在地图状态栏和第二页提示“设施正在补充”。

**普通专家分析只读已有 POI 缓存，发出 0 次在线请求。**缓存不足仍展示已有候选，并提示数据不完整；
“刷新 POI（调用 API）”是显式在线操作。没有新增绑定入口时不再调用第二次 C++；有新入口时使用
`facilitiesOnly`，复用第一轮等时圈，不重复补面、填洞或分析未核齐类别的灰区。已核查类别仍保留完整覆盖计算。
设施阶段失败不撤掉等时圈。原始图数据与精度规则没有因提速而改变，清单不足不代表真实设施匮乏。

第二页可展开实际阶段耗时，`firstResult` 是后端首轮结果准备时长，`total` 是后台任务时长；
二者不包含 HTTP 和浏览器绘制，`networkLoad` 单独记录。`cpp.*` 是原生阶段耗时，
包括输入解析、图校验、吸附、建图、Dijkstra 和展示面；`facilityCpp.*` 是设施专用调用。

固定区域 POI 可提前填入共享缓存。从仓库根目录运行：

```powershell
# 默认仅规划，不调用在线 API。
.venv/Scripts/python.exe backend/scripts/precache_demo_pois.py
# 明确允许在线预采集；限额和未完成状态会输出。已有页优先复用。
.venv/Scripts/python.exe backend/scripts/precache_demo_pois.py --fetch --max-requests 16 --budget-seconds 12
```

预采集只写现有、被 Git 忽略的缓存，不更新路网或生成待提交的 SVG。一次运行可能受预算限制而不完整；
后续运行补缺页，不强制刷新已缓存页。`--fetch` 需要本地服务端 AK，本轮测试没有运行在线预采集。

### 可选：百度真实底图

复制 `frontend/.env.example` 为 `frontend/.env.local`，将可用于浏览器的百度地图 JavaScript API AK 填入 `VITE_BAIDU_BROWSER_AK`，并在百度控制台配置本地开发域名。**不要提交 `.env.local`，也不要放服务端私密 AK**：`VITE_` 值会进入浏览器。暂时没有 AK 时，页面仍能运行，展示带来源署名的 OSM 道路 SVG 预览；它不是百度地图截图或百度瓦片的 SVG 导出。

有 AK 时，页面使用百度 JSAPI 4 显示真实底图，直接读取已生成的 `src/data/demoMap.bd09.json` 叠加 SVG；**页面初始化、选点与模式切换不再调用 `BMap.Convertor`**。固定边界、中心点和外围展示范围已由 Python 使用百度官方坐标转换服务一次性生成。快速／专家模式共用一个地图实例，切换时不重新初始化底图。地图关闭百度原生滚轮连续缩放，由前端滚轮切换大／中／小档；地图外滚轮仍用于翻页，中／大档可拖动。AK 缺失或底图初始化失败时回退到 SVG；边界校验失败则保留底图、单独提示并暂停百度图上的选点。网络和浏览器 AK 服务权限仍需有效。

现有 BD‑09 文件可直接使用，不需要每次启动转换。只有修改 WGS‑84 边界、局部原点或外围扩展距离时，才从仓库根目录运行：

```powershell
.venv/Scripts/python.exe backend/scripts/export_demo_map_bd09.py
```

脚本读取服务端 `BAIDU_SERVER_AK`；输入未变化时直接复用已生成文件，发出 **0 次 API 请求**。`--refresh` 仅用于明确要求重新转换，不加入启动脚本。转换失败不会覆盖上次有效文件；更新后请复核四个路口与沿线对齐。详细说明见 [固定地图数据与请求说明](../docs/baidu-map-assets.md)。

### 范围和数据边界

展示区由国帆路（北）、江湾城路（东）、殷高东路（南）、国权北路（西）道路中心线围成，是**项目自定义演示范围，不是行政边界**。路段折线来自 OpenStreetMap；原始 WGS‑84 GeoJSON 在 `src/data/demoBoundary.wgs84.json`，扩展后的无 AK 道路预览在 `src/data/demoContext.extended.wgs84.json`，原始 `demoContext.wgs84.json` 保留不覆盖。来源及 ODbL 许可见数据属性和页面署名。`scripts/build-demo-boundary.mjs` 与 `scripts/build-demo-context.mjs` 记录了一次性提取方式；重新运行会访问 Overpass，需复核新数据，不应直接覆盖已审核资源。

虚线围合区只限制起点；底图数据范围在四路边界的外接框四周额外扩展 1,300 米，覆盖 900 秒 × 1.3 米／秒的理论直线外延并留有余量。缩放等级分别为小档 1.5×、中档 3×、大档 5×；小档也会裁去部分外围画面，中／大档可拖动查看。无 AK 的 SVG 道路与绿地数据覆盖扩展范围，建筑只保留选区周围 450 米以控制体积。区内点击记录候选点，区外点击提示范围限制；“快速模式”通过百度步行采样和 Python 插值展示**近似等时圈**，不是完整路网遍历。真实计算仍须检查该点是否位于公共步行空间、能否接入路网。**起点选区不用于裁剪真实 15 分钟路网或等时圈**，路网和设施必须覆盖所有区内起点可能到达的外围。当前没有实地核实的正式体检报告。

## 目前可操作的内容

- 默认“快速模式”下，在四路围合区内选点，再点击右上角“生成采样等时圈”：后端返回不规则近似等时圈与代表性步行路线。重新选点会清除旧结果；再次分析会重新请求。没有服务端 AK 时可选点，但在线分析会失败并提示重试。
- 切换到“专家模式”后，在同一份底图内选点，点击右上角“计算 15 分钟等时圈”；C++ 返回 MultiPolygon 和可达街段并在地图上动画呈现，同时显示圈内五类候选 POI。第二屏展示路网计数、到街边的估算时间、POI 分类统计与数据精度说明。
- 地图右侧提供“大／中／小”三级比例视图：相对完整范围基准分别为 5×、3×、1.5×，大档围绕已选点。默认显示中档；切换时有短暂平滑过渡。中／大档可按住拖动底图，小档固定在中心视野。真实范围 SVG 预览与合成算法演示共用这一选择。地图内滚轮向上逐档放大、向下逐档缩小，与按钮共用状态和动画；到达大／小档后继续滚动也不翻页。触控板累计 48 像素滚动量后切一档，切档后有 460 毫秒防抖，像素／行／页单位均规范化处理。横向滚动不切档，Ctrl＋滚轮及触控板捏合保留浏览器缩放；“全圈”状态向上滚动进入中档、向下进入小档，不清空计算结果或触发计算。百度原生连续滚轮缩放仍关闭。
- 第一屏分为项目信息、横向铺满的地图和 `LIVING CIRCLE` 字样三部分。顶部导航提供“隐藏字样／显示字样”按钮（小屏使用眼睛图标），支持 Tab 聚焦、Enter/Space 操作。每次进入页面默认显示，不保存隐藏偏好；收起／展开采用约 420 毫秒的高度过渡，字样轻微下移并淡出，保持原有字体比例，地图同步扩展。快速重复点击可中途反向切换；整个显隐过程只改变地图可见面积，不改变百度及 SVG 底图的实际比例尺、视野中心或拖动位置，不在动画结束后自动取景。仅在初次加载、主动切档或点击“全圈”时适配视野，不重建地图、不清空选点或分析结果。隐藏时暂停字母动画；开启“减少动态效果”时立即切换并停止字母动效。底部字母的分层错位效果自动循环，不依赖鼠标位置。
- 地图外滚轮累计滑动一定距离后整屏翻页：地图演示独占第一页，控制面板在第二页；触屏可上下滑动，也可使用页面导航按钮；第二页仍可在页内滚动。
- 起点以小圆点显示：绿色为已分析起点，橙色为待分析起点。
- 桌面鼠标在地图上显示“步行探针”；可在围合区内选点。合成模式可筛选和查看候选 POI，仍不把未经核实的在线清单用于真实灰区判定。
- 主按钮与地图结果有按下、处理中和完成反馈；触屏与“减少动态效果”模式保留功能但收敛动画。
- 第二页内容较长时可在页内滚动；窄屏下起点、结果、服务类别顺序堆叠。
- 结果页底部展示装饰性社区插画与“一个起点，连接生活。”字样。

入口是 `src/entry.js`。主界面位于 `src/App.vue`，两模式共用的地图位于 `src/RealMapStage.vue`，地图坐标与 GeoJSON→SVG 投影在 `src/mapGeometry.js`；主样式、真实地图样式分别在 `src/demo.css`、`src/realMap.css`。原有的 `src/main.js` 和 `src/styles.css` 暂时保留，不被新入口使用。

## 后续真实数据对接

`vite.config.js` 已将 `/api` 代理到本地 `8000` 端口。`src/sampledAnalysisClient.js` 用于“快速模式”的百度采样结果；`src/cppAnalysisClient.js` 用于“专家模式”，把 Python/C++ 输出规范化到地图显示契约。`App.vue` 独立管理两模式的选点、状态与重试；`RealMapStage.vue` 只消费结果并负责 SVG/百度投影与动画。不要将采样近似面或未核实合成路网用于正式报告。

地图展示适配层使用 `coordinateSystem`、`displayArea` 和 `routeSegments`。“快速模式”返回 `bd09ll` 的 `MultiPolygon` 与代表路线，并保留局部坐标的备用展示面；“专家模式”返回 `preview-local-v1` 的 MultiPolygon 与可达街段。路线动画顺序只用于展示，不代表逐街段耗时。地图坐标与选点反算使用 `demoMap.bd09.json` 中的官方 250 米校准网格；页面不调用在线 Convertor。坐标对齐不等于路网和入口已核实，仍不能据此输出真实覆盖结论。详情见 [固定地图与校准说明](../docs/baidu-map-assets.md)。

### 选区内合成道路图（建模第一阶段）

`src/data/demoRoadGraph.local.json` 是与无 AK 的 SVG 底图对齐的 `preview-local-v1` 局部坐标图：`selectionBoundary` 保留四路围合的起点选区；`coverageBoundary` 是该边界外接框四周扩展 1,300 米后的道路建模矩形，与地图全览基准范围使用同一套 `expandedLocalBounds` 计算。`nodes` 存节点 ID 与 `x/y`；`edges` 存两端 ID、`roadMajor`／`roadLocal`／`roadPath`／`inferredJunction` 类别、来源 way ID 和局部长度；`junctions` 是共有顶点，`inferredJunctions` 单独记录未核实的推断连接。图中**没有 WGS‑84 或 BD‑09 运行时坐标**。`node scripts/build-demo-road-graph.mjs --write` 可从已保存的 `demoContext.extended.wgs84.json` 重建它；校核 SVG 可按需用 `node scripts/render-demo-road-graph.mjs --write` 在本地生成，不随仓库提交。

建图保留整个 `coverageBoundary` 内的道路折线，穿越四路围合边界的同一来源道路不再被截断；起点仍只能落在 `selectionBoundary` 内。原始 SVG 已做约 2 米折线简化，导致一些真实道路端点靠近另一条线段，却不再共享顶点。`src/roadGraphRepair.js` 只对**不同连通片**中相距不超过 1.5 米的端点—线段做推断补连：拆开目标线段，并增加一条短 `inferredJunction` 边；明显平行的端点—线段关系不补，线段中部彼此相交也不自动补。每个推断均为 `verified: false`，可与原始道路边区分。

补连前为 7,492 节点、6,886 边、875 个连通片；补连后为 8,518 节点、9,232 边、1,320 条推断连接记录、72 个连通片。`node scripts/audit-demo-road-graph.mjs` 输出全图端点、未消除的近距断点及当前示例起点的连通统计；追加 `--details` 可列出周边所有端点。需要人工校对时，可运行 `node scripts/render-demo-connectivity.mjs --write` 在本地生成 SVG；生成图不参与运行，也不提交。测试覆盖端点接入、平行近邻不接、几何交叉不接、边长／ID／范围一致性和示例起点的路线延伸。

由于仍缺少原始 OSM 节点 ID、桥梁／隧道层级、步行权限、人行道及合法过街标注，这只是**用于路线动画的合成模型**，不能据此宣称真实步行可达。剩余 72 个连通片和近距断点需要继续核查；桌面宽屏或拖动时可能露出基准矩形外少量底图，那里尚未保证完整路网。真实版必须以可能到达的范围而非屏幕边缘决定数据覆盖，并用可信数据核实连接与过街，再由后端结果替换示意圆与路线。
